# Preference hints gate on skill progression, not on discovery

PR #143 hid every preference hint (treat/posture/pet-spot) until the player had already guessed it correctly at least once. That made hints purely confirmatory — useless for finding an answer you didn't already have, which undercut the point of a hint. We're gating vague hints on skill progression instead: each type's vague clue appears once its mapped **Taming skill** (body-language→posture, petting-technique→pet-spot, treat-cooking→treat) reaches tier 2 (its first completed level), regardless of whether that specific preference has been discovered yet, and stays visible permanently from then on.

A single shared toggletip — reusing the existing `src/components/Toggletip` component (already used in `EnergyPlanner.tsx`, absolutely positioned so it never reflows surrounding layout on open, widened from `content: string` to `content: React.ReactNode` to fit the richer per-type sections) — appears on the card once the *first* of the three skills reaches tier 3, whichever that is for a given playthrough. Each preference type gets its own section inside it once that type's vague hint is already showing (tier 2+), and that section's own content depth still tracks that type's own skill tier independently of what triggered the toggletip's appearance: it reveals the confirmed hint at tier 3 for that type, then upgrades to a full log of every specific option tried so far (right or wrong) at tier 4 for that type — built deliberately as an elimination aid for narrowing down an undiscovered preference, not as a trophy case for a found one.

This replaces `hasClearHints` (a global `body-language.tier + petting-technique.tier >= 6` sum) entirely — nothing else depended on it. It also adds a new `triedPreferences` state field, species-keyed in parallel with the existing `discoveredPreferences`, recording every specific value attempted per type; the old schema only stored a boolean "confirmed" per (species, kind) with no record of which wrong options had been tried, which the tier-4 elimination log needs.

**Considered and rejected:**
- Per-type independent toggletips (one inline per hint line) — rejected in favor of one shared toggletip with a single appearance trigger, simpler to reason about than three separately-appearing disclosures.
- Native `<details>/<summary>` for the toggletip, or a new `@radix-ui/react-popover` dependency — both rejected once the existing `Toggletip` component (already absolutely-positioned, already accessible, already used in `EnergyPlanner.tsx`) turned up; reusing it needs no new dependency and no new a11y work.

**Addendum (2026-08-13, issue #159):** "stays visible permanently" above is superseded once the toggletip exists. Once any skill reaches tier 3 and the toggletip appears, every visible vague hint moves into it (`PreferenceDetails` shows the vague hint itself in place of the old "Keep training to learn more." placeholder) instead of also sitting in the card body — three hint paragraphs stacked above an already-open toggletip was most of a card's height on mobile. Before the toggletip exists, a vague hint still renders directly on the card exactly as originally decided; only the post-toggletip window changed.
